用 500 行 Python 生成一个静态博客，并部署到 GitHub Pages

2026 年 9 月 28 日 · 约 16 分钟 · Python网站工具

##为什么自己做

现成的博客工具很多：Hexo、Hugo、WordPress。自己写的理由只有一个 —— 我想要的东西很简单，不想为了它装一整条工具链。

我的需求：

  • 文章用 Markdown 写，放在一个文件夹里
  • 一条命令生成整站
  • 输出是纯 HTML/CSS/JS，能直接丢到任何静态托管上
  • 不引入 Node、不装前端框架、不需要数据库

结果是一个约 500 行的 Python 脚本，只依赖 markdown 和 pygments。

##一、静态站 vs 动态站

先说清楚这个选择的代价。

静态站（本站） 动态站（WordPress 等）
内容存放 Markdown 文件 数据库
生成方式 构建时一次性生成 HTML 每次访问现查数据库
服务器 不需要（托管平台发文件） 需要 PHP/Node + 数据库
费用 基本免费 服务器 + 数据库要钱
打开速度 极快（就是普通文件） 取决于数据库和缓存
被攻击面 几乎没有（没有可执行后端） 插件/后台是主要入口
在线编辑 ❌ 要本地改文件再重新构建 ✅ 浏览器里就能写
评论/搜索 要外挂第三方服务 插件支持
多人协作 靠 Git 内置用户系统

判断标准很简单：一个人写、不需要在线编辑后台 → 静态站。多人写、需要可视化编辑、要装各种插件 → 动态站。

生成器做四件事：

  1. 读：扫描 posts/*.md，解析文件头的元信息
  2. 转：Markdown → HTML，代码块做语法高亮
  3. 拼：套上页面模板，生成列表页、详情页、标签页、归档页
  4. 写：输出到 dist/，连同 CSS/JS 和 RSS

##三、文章格式：文件头 + 正文

每篇文章开头写一小段元信息，其余就是普通 Markdown（外层用四个反引号，方便里面嵌套三个反引号的代码块）：

---
title: 用 Python 从一本 467 页的 PDF 教科书里统计词频
date: 2026-10-11
tags: Python, 文本处理, 数据清洗
summary: 从 PDF 提取全部单词并排序看起来很简单，真正的工作量全在清洗上。
---

## 正文从这里开始

普通段落，支持 **加粗**、`行内代码`、[链接](https://example.com)。

解析文件头只要十几行，不需要 YAML 库：

def parse_front_matter(text):
    meta = {}
    lines = text.splitlines()
    if lines and lines[0].strip() == "---":
        for i in range(1, len(lines)):
            if lines[i].strip() == "---":
                return meta, "\n".join(lines[i + 1:])
            if ":" in lines[i]:
                key, _, value = lines[i].partition(":")
                meta[key.strip().lower()] = value.strip()
    return meta, text

##四、Markdown 渲染与代码高亮

MD = markdown.Markdown(
    extensions=["fenced_code", "codehilite", "toc", "tables", "attr_list"],
    extension_configs={
        "codehilite": {"guess_lang": False, "css_class": "highlight"},
        "toc": {"toc_depth": "2-3"},
    },
)
  • fenced_code —— 支持 ``` 围栏代码块
  • codehilite —— 配合 Pygments 做语法高亮
  • toc —— 自动给标题加 id 并生成目录

有一个小细节要注意：codehilite 默认会猜语言。猜错的后果是代码被染成乱七八糟的颜色，所以我把 guess_lang 关掉，只认我明确标注的语言。

高亮的配色不手写 CSS，直接用 Pygments 生成，能和主题保持一致：

from pygments.formatters import HtmlFormatter
(DIST / "pygments.css").write_text(
    HtmlFormatter(style="monokai").get_style_defs(".highlight"),
    encoding="utf-8")

##五、页面模板：用一个函数包住所有页面

所有页面共享同一套外壳（导航、页脚、主题切换按钮），所以只需要一个函数：

def page(title, content, *, active="", description=""):
    return f"""<!DOCTYPE html>
<html lang="zh-CN" data-theme="dark">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>{html.escape(title)}</title>
  <link rel="stylesheet" href="{SITE['base_url']}/style.css">
</head>
<body>
  <header>...导航...</header>
  <main>{content}</main>
  <footer>...</footer>
  <script src="{SITE['base_url']}/main.js"></script>
</body>
</html>
"""

⚠️ 一定要 html.escape()。文章标题里出现 &、< 是常事，不转义就会破坏页面结构，甚至造成 XSS。这个函数出现的每一处都别偷懒。

##六、深色模式：不要闪白

主题切换本身很简单，难点是首屏不能闪。

如果等 JS 加载完再设置主题，深色模式用户会看到一瞬间的白屏（FOUC）。解决办法是让 JS 尽早执行，并且默认跟随系统：

function preferredTheme() {
  var saved = localStorage.getItem("blog-theme");
  if (saved) return saved;                       // 用户手动选过
  return matchMedia("(prefers-color-scheme: light)").matches ? "light" : "dark";
}
applyTheme(preferredTheme());                    // 立即执行，不等 DOMContentLoaded

样式全部用 CSS 变量，切换主题只是改一个属性：

:root { --bg: #0e1117; --text: #e6edf5; --accent: #3ddc97; }
html[data-theme="light"] { --bg: #fff; --text: #1f2933; --accent: #0e8f63; }

body { background: var(--bg); color: var(--text); transition: background .25s; }

##七、几个让阅读体验变好的小细节

细节 做法
代码一键复制 JS 给每个代码块追加按钮，优先用 navigator.clipboard，失败退回 execCommand
长文阅读进度 顶部一条 2px 的进度条，算的是文章底部相对视口的位置
目录 只在标题数 ≥ 3 时才显示，太短的文章不需要
中文排版 line-height: 1.85、正文最大宽度 860px（约 40 个汉字）
手机适配 680px 断点，导航换行，卡片缩小内边距
无障碍 语义化标签、<time datetime>、"跳到正文"链接、prefers-reduced-motion
打印 @media print 隐藏导航和目录，白底黑字

中文排版那条值得强调：正文宽度不要超过 900px。一行字太长，眼睛回到下一行时容易串行，这是中文博客最常见的排版问题。

##九、部署到 GitHub Pages

准备：注册 GitHub 账号（免费）。

##1. 建仓库

新建一个仓库，命名有讲究：

仓库名 网址会是 类型
你的用户名.github.io https://你的用户名.github.io/ 用户站（根路径）
其他任意名字（如 blog） https://你的用户名.github.io/blog/ 项目站（子路径）

##2. 改一处配置

项目站部署在子路径下，如果资源路径写的是 /style.css，就会 404。所以生成器里要留一个 base_url：

SITE = {
    "title": "代码手记",
    "author": "你的名字",
    # 项目站填 "/仓库名"；用户站或自定义域名填空字符串
    "base_url": "/blog",
}

改完之后所有链接、CSS、JS 路径都会自动带上这个前缀。

##3. 推上去

cd blog
git init
git add .
git commit -m "初始化博客"
git branch -M main
git remote add origin https://github.com/你的用户名/blog.git
git push -u origin main

##4. 开启 Pages

仓库 → Settings → Pages → Source 选 Deploy from a branch → 分支选 main，目录选 / (root) → Save。

如果你把 dist/ 内容直接放在仓库根目录，就选 root；如果保留 dist/ 目录结构，就选 /docs 并改名为 docs，或者用 GitHub Actions 构建。最简单的做法是把 dist/ 里的内容推到仓库根目录。

##5. 等一两分钟

访问 https://你的用户名.github.io/blog/。第一次可能要等 1~3 分钟，之后每次 git push 自动更新。

##6. 绑定自己的域名（可选）

在仓库根目录建一个名为 CNAME 的文件（无扩展名），内容只写域名：

blog.example.com

然后在你的域名服务商那里加一条 CNAME 记录指向 你的用户名.github.io。GitHub 会自动签发 HTTPS 证书。

我特意在构建时生成了一个 CNAME.example 说明文件，就是提醒这一步 —— 但记得把它删掉，否则它会出现在你的站点里。

##十、踩过的坑

1. 子路径 404 现象：本地打开正常，部署后页面没样式。 原因：base_url 没配。用户站和项目站的路径结构不同，这是新手最常踩的一个。

2. 下划线开头的目录被 Jekyll 吃掉 GitHub Pages 默认会用 Jekyll 处理你的文件，而 Jekyll 会忽略下划线开头的文件/目录。如果文章路径里有 _posts 之类，就会 404。解决：在根目录放一个空的 .nojekyll 文件（生成器已经自动生成了）。

3. 中文文件名变乱码 文章文件名建议用英文 slug（如 word-frequency-from-pdf.md），中文标题放在 front matter 里。URL 里带中文虽然能用，但分享出去容易被转义成一长串 %E7%94%A8...。

4. 图片路径忘记加前缀 同理 base_url。建议文章里的图片也用绝对路径写。

##小结

这套方案的核心是把复杂度留在构建时：运行时没有数据库、没有服务端、没有框架，浏览器拿到的就是最终 HTML。

代价是：

  • 没有在线编辑后台，改文章要本地改文件再重新构建、推送
  • 评论要外挂（比如 Giscus，基于 GitHub Discussions，免费）
  • 搜索只能靠外部服务或浏览器查找

如果你能接受这三点，静态博客几乎是零成本、零维护的最佳选择 —— 一年托管费 0 元，被攻击概率接近 0，访问速度还比大多数动态站快。

完整生成器约 500 行，只依赖 markdown 和 pygments 两个库。
